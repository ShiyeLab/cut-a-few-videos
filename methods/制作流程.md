# Agent 制作流程

从用户给出的材料出发。主 Agent 负责策划、判断和执行，使用者提供目标、素材、偏好和所需服务配置。默认主 Agent 为 DeepSeek V4.1 Flash，也可换用其他能调用工具的模型。视频理解由 MediaKit 执行，主 Agent 阅读返回的内容分析与建议区间，再进行编排。

## 1. 接收并盘点素材

先读用户要求与所有提供材料，填写[素材清单](../templates/video/inventory.md)，同时把明确的目标写入[本条要求](../templates/video/brief.md)。不要把需要 Agent 填写的技术配置转交给用户。

| 材料 | 需要看什么 | 记录什么 |
| --- | --- | --- |
| 文字资料与口播 | 内容事实、用途、是否已有定稿、允许改动范围 | 可用文案、需核对的说法、预期时长 |
| 图片 | 主体、尺寸、清晰度、真实产品与页面 | 数量、可用用途、需避开的裁切 |
| 视频 | 实际动作、连续片段、画面尺寸；现成推书成片的中间内容区是否夹带原片字幕或文字 | 文件时长、可用源区间、适合哪句口播、竖向截取位置 |
| 录音与配音 | 内容是否完整、音色、停顿、噪声、末句 | 是否直接复用、有无匹配时间轴 |
| 海报与设计 | 是否无字、上下能否裁切、风格是否适合 | 可复用底图或新的生图需求 |

视频按[MediaKit 接入步骤](../docs/video-understanding.md)提交并查询完成，用分析结果填写实际内容和候选区间。主 Agent 不能用文件名、排序或生成提示词替代视觉理解。缺少配置或分析失败时先解决这一环，不跳过后直接排镜头。

图片使用图像理解工具或用户已确认的内容说明；音频按需调用转写、分析工具。没有实际视听能力时，不把主模型的推断写成“已看过”或“已听过”。素材数量不代表能覆盖口播；长视频也要按实际可用区间计算。原件保留，整理与转码另存。

## 2. 根据材料决定怎么做

把各项选择与理由写入 `brief.md`。用户已明确的要求直接采用；一般制作细节由 Agent 决定。只有确实影响成片的缺项、内容方向、偏好或未授权费用需要集中询问。

| 判断 | 处理 |
| --- | --- |
| 已有完整口播吗 | 有定稿就按要求保留；只有资料则先形成有依据的口播；无旁白需求则走无人声版 |
| 已有可用声音吗 | 内容、听感都合适时复用；需要新声音时选声、短试听，再合成完整口播 |
| 画面是否足够 | 优先真实素材；缺动作可检索或补拍，缺环境可生成；不为了使用 API 而替换足够的实拍 |
| 出几条、怎么错开 | 条数由用户定。多条时按下文“多条成片”错开选段、顺序、运镜、转场、贴片与开头钩子 |
| 贴片怎么做 | 有合适无字底图就复用，否则默认调用生图 API，按内容设计同一张上下贯通的海报 |
| 用哪些服务 | 用户指定的优先，否则采用默认推荐；各环节独立选择，记录所用服务与模型 |
| 视频理解是否完成 | 默认 MediaKit，保存完成的分析、实际内容与候选区间；失败先处理，不让主模型猜测画面 |
| 能否开始生成 | 核对需要补的素材、生成数量、预算和所需配置；已获授权的操作直接执行 |

成片不配乐，`music` 保持 null；用户在剪映中自行添加。

### 多条成片

同一批成片共用素材理解结果，每条在 `projects/my-video/variants/<编号>/` 下保存自己的 `project.json`、`scenes.json`、`layout.json` 与贴片底图，输出到 `projects/my-video/out/<编号>-v1`。在 `brief.md` 的差异表里逐条记录以下选择，并确认任意两条至少有四项不同：

| 维度 | 怎样错开 |
| --- | --- |
| 开头钩子 | 只改开头一两句，正文一字不改；改了钩子的条目需要自己的 `script.txt`、配音与时间轴 |
| 选段与顺序 | 同一句口播换用不同的可用源区间或不同素材；允许调整句内配图的先后 |
| 运镜 | 同一张图换用 push、pull 或不同方向的平移 |
| 转场 | 同一切点换用不同的顺滑转场 |
| 贴片 | 每条重新生成底图并换配色；标题措辞可不同 |
| 音色 | 按内容设计；只有内容支持多种演绎时才换 |

## 3. 准备内容、声音与真实时间轴

图书或产品事实来自用户资料；引用核对原件，不编造内页、页码或使用过程。纯口播保存为 `script.txt`，镜头说明与演绎要求分开。

默认采用豆包 2.0 流式语气方案，也可换用其他配音 API。音色要设计，不套用默认值：先从介绍资料与脚本研究这本书的题材、目标读者和各段情绪走向，再据此指定讲述者形象、音色与演绎要求，把依据写入 `brief.md`。音色不固定年龄、性别或声线。以完整意思连贯说话，停顿放在语义转换与自然换气处；不逐字发力或切碎词组。演绎要求独立保存，字幕切条不决定朗读停顿。代表性短段试听后，再听完整口播。

声音确定后生成 `timeline.json`，每条包含实际开始秒数、结束秒数和文字。有字级时间的服务可直接整理；其他配音或自己录音可通过转写与对齐服务或人工标注取得真实时间，逐句核对。不能按字数平均估时。更换声音、语速或文案后重做时间轴。

无需人声时明确设置 `voice: null` 与片长 `duration`，按画面节奏安排字幕；不要为了满足工具输入而生成无用配音。

## 4. 选镜头与补画面

先把每句口播的意思写成可见动作与场景，再找素材。比如“工作消耗”可对应停下打字、看着文件迟疑；“读到共鸣”可对应手指停在真实书页、读完抬眼。抽象词只用于理解内容，不能代替实际画面核对。

产品封面、内页、翻页和抄写使用对应产品的真实素材。缺少落笔实拍时可展示真实已写页面，不用另一本书或通用笔记本冒充。外部素材补人物动作、情绪与环境。

环境与情绪镜头可用默认 MiniMax H3，也可用其他视频 API。先结合口播和前后镜头设计可见变化，再写清主体、动作、光线、镜头、时长与禁止内容。新 AI 环境镜头默认无文字、无书本、无手；人物是否入镜按内容选择，例如虚化背影可用于情绪表达，不能冒充产品使用实拍。生成后也要调用视频理解工具检查实际片段，核对物体、运动、禁用内容和可用时长，不能仅根据生成提示词认定结果合格。

用户给的现成推书成片只取画面：其上下包装与我们的贴片位置相同，截取中间内容区即可，必要时用 `focus_y` 调整竖向位置；原声与原配乐不用，也不擦字幕。选段时确认区间在中央窗内没有原片字幕或文字，有的就换区间。

先将分析依据与不确定项写入 `inventory.md`，再由主 Agent 把采用决定写入 `scenes.json` 与 `sources.json`。服务建议的区间仍需核对源时长、前后切镜、中央窗裁切和转场所需的额外尾段；可疑区间交理解工具复核。

转场与运镜按镜头设计，取值见[工程说明](../docs/工程说明.md#3-单条配置)：

- **转场**：同类画面之间用 `fade` 叠化；画面内容或情绪转折用 `flash_white`、`flash_black`；顺着前镜运动方向接下一镜用 `push_*`；场景平稳切换用 `soft_*`。全片不要只用一种，也不要相邻切点连续使用同一种推入方向。
- **运镜**：静态图默认带 `move`，与前后镜头的运动方向衔接，例如前镜 `pan_left` 接 `push_left` 转场。全片速度由 `move_rate` 统一，不逐镜调速。视频素材本身有动作时一般不加运镜。

## 5. 生成贴片并排字

默认调用 Seedream 5.0 Pro，也可换成其他生图 API。按内容确定色彩、质感与边缘元素，生成一张 9:16 无字海报，取其上下两端做贴片。底图不含文字、印章、logo 或边框，标题与底部文字留给程序排版。

按[海报提示词](../templates/poster-prompt.txt)准备具体提示词，输出本地 PNG/JPG，将路径填入 `project.json` 的 `band_art`。去掉白卡片，文字使用中文字体、细描边和轻微深色投影，不用模糊白光糊住底图。修改标题只重排文字，换内容或风格才重新设计底图。

## 6. 合成

按[工程说明](../docs/工程说明.md)填写布局、镜头和项目配置，所有素材路径从仓库根目录算起：

```sh
python tools/build_video.py --project projects/my-video/project.json --work projects/my-video/v1
```

工具根据实际声音和片尾留白计算总长，按句首安排镜头，绘制文字并完成运镜、转场、人声处理和合成。既无声音文件也无旁白时，配置中明确填写 `duration`。多条成片时对每条的 `project.json` 分别运行，输出到各自目录。

## 7. 看完整成片并交付

核对每句意思和画面，特别是转折、产品出现与结尾；检查最长字幕、标题和末句，以及词组连贯、自然换气和最后一字；多条时核对差异表与实际成片一致。这些检查通过视听工具或实际观看、试听进行；主 Agent 根据检查结果记录，仍需用户确认的项目明确列出。保留完整片尾，不通过缩短成片掩盖时间不够的问题。

交付新版本的 `video.mp4`、配置与检查结果，注明实际检查和需用户决定的事项。用户提出修改后，只重做受影响环节；素材、声音、提示词与既有版本可复用。
