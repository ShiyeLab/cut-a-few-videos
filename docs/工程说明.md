# 剪几个视频：工程说明

## 1. 制作过程与分工

输入是口播稿、与声音对应的时间轴、真实素材、贴片底图和本条视频的布局配置。输出是 1080×1920 的 MP4，以及可修改的字幕、镜头表、布局和检查文件。

默认推荐的主 Agent 为 DeepSeek V4.1 Flash，也可使用宿主支持的其他模型。Agent 先盘点材料，确定是否配音、是否配乐和画面缺口，再把口播意思落实成可见动作与场景，选择音色和配色。本地程序依这些决定排时间、绘文字和合成视频。主模型由使用者在 Agent 宿主中选择，宿主需能读写文件、执行命令和检查媒体。

完整流程见[制作流程](../methods/制作流程.md)。主模型、生图、视频、配音与检索可逐环节替换，Agent 将所选服务的产物整理为本地图片、视频、声音和时间轴，随后按相同方式合成。更换步骤见[服务选择与替换](optional-services.md)。

## 3. 单条配置

`build_video.py --project 配置文件 --work 新目录` 读取以下字段。文件路径相对仓库根目录，不是相对 JSON 所在目录。

| 字段 | 含义 |
| --- | --- |
| `title`、`footer` | 顶部标题与底部文字；可以用 `\n` 明确换行 |
| `layout` | 本条视频的布局 JSON；从通用布局复制后修改 |
| `band_art` | 生图 API 生成的无字海报路径；已有合适底图可复用。null 用于用户选择无底图包装时 |
| `script` | 纯口播 UTF-8 文本；忽略空行和以 `#` 开头的说明行 |
| `timeline` | 与完整声音匹配的字幕时间轴 |
| `scenes` | 以口播句首定位的镜头表 |
| `voice` | 人声音频路径；无配音时为 null |
| `music` | 独立配乐路径；不用配乐时为 null |
| `music_gain` | 音乐相对人声目标响度的差值，默认 -14 |
| `tail` | 配音文件后保留的秒数，默认 1.2；片长向上取整到完整帧 |
| `duration` | 显式片长；有配音时不能短于配音。没有配音文件时必填 |
| `transition` | 中央叠化秒数，默认 8 帧；按帧率取整 |

`--no-voice` 关闭最终人声，但仍读取配置中声音的长度，保持原片长。`--no-music` 关闭配乐。两者同时使用为全静音；文件仍保留静音 AAC 音轨。

Agent 根据素材与要求填写参数，`build_video.py` 读取配置并调用 `layout.py`、`compose.py`。合成入口只接收文件，不检查生成图片、视频或声音的服务品牌。

### 时间轴与镜头表

时间轴是一个数组，每条包含 `start`、`end`、`text`，时间单位为秒。生产配音从服务字级结果整理，自己录音则按实际音频标注。示例中的手工秒数只用于无口播教学片。

```json
[
  {"start": 0.2, "end": 2.4, "text": "先看眼前的画面。"},
  {"start": 2.8, "end": 5.0, "text": "再把注意力放回此刻。"}
]
```

`scenes.json` 的 `anchor` 是该镜开始时的口播句首。程序去掉标点、按句首匹配，必须唯一命中一条字幕。首镜用 null，从 0 秒开始；后续镜头按口播顺序排列。

```json
[
  {"anchor": null, "asset": "projects/my-video/assets/cover.png", "fit": "blur", "reason": "先展示本书"},
  {"anchor": "再把注意力", "asset": "projects/my-video/assets/turn.mp4", "in": 1.2, "fit": "cover", "reason": "本书实际翻页"}
]
```

准备后生成的 `shots.json` 增加成片时间 `start/end`；`in` 是源视频起点，`speed` 默认 1，可取 0.5—2。不会自动慢放或循环短素材来凑片长；不足则换选段、换素材或调整镜头分配。

`fit` 有三种：`cover` 等比裁满中央窗；`contain` 保留整张并补底色；`blur` 用模糊图填底、前景保留完整画面。`focus` 可为 left、center、right，只影响 cover 的横向裁切。静态图 `zoom: 0.035` 表示整镜推近 3.5%；当前只实现居中推近。

## 4. 时间与转场如何对齐

镜头起点取自实际字幕时间，并对齐到整帧。第一镜从 0 开始，镜头之间连续，末镜铺到目标片尾。字幕显示提前 0.03 秒，句尾最多延长 0.12 秒，并避开下一句；最后一句保持到片尾。正文去标点后的文字必须和时间轴完整一致，禁止以均分时长掩盖漏字。

叠化只作用在中央窗。为避免转场吞掉片长，每个非末镜会额外读取一段等于转场时长的尾部。因此视频源至少要有：`in + (该镜时长 + 转场时长) × speed`。源区间不足会报错，不能靠截短配音解决。

静态图在 4 倍画布上计算推近，再回到输出尺寸，并用平滑起停曲线控制进度。这样减少小幅移动时逐像素跳动，计算比静止图更重。推近比例应小，检查连续画面而不只看抽帧。

## 5. 版式与声音

默认画布 1080×1920、30 fps；上条带 380 像素，中央窗 1080×1150，下条带 390 像素。字幕位于中央画面的下方区域，底部文字限制在 y=1760 以上。

贴片默认由生图 API 生成整幅无字海报，再用 `band_art` 导入。每条视频复制布局再设计配色。实际基础背景取 `bands.*.fill`，实际字体取 `fonts.*`，只改 `theme` 记录不会自动换掉所有绘制颜色。每个文本块支持字号、最小字号、最大行数、行距、字色、描边和可选投影；放不下就报错，不裁字。

布局里的纯色填充用于没有底图时的基础排版；离线教学例使用程序绘制的底图。设置 `band_art` 后隐藏中间标题卡，标题直接排在上条带。上下条带对同一张海报等比放大，分别取顶端和底端。程序覆盖标题与底部文字框位置，并加 3 像素描边、轻微投影。若要精调这些坐标，可准备后修改本版布局，再重画标题卡并直接合成。

字幕先渲染为透明 PNG，再拼成 QTRLE 透明视频轨，最后叠加到中央画面上。正文字体与换行由 Pillow 控制，不需要 FFmpeg 文字滤镜。

人声默认统一到 -16 LUFS。配乐按 `music_gain` 设定目标响度，必要时循环铺满，开头渐入、结尾渐出；同时有人声时再适度压低音乐。四种组合分别是人声与音乐、只有人声、只有音乐、全静音。背景视频的音轨完全丢弃。`audio_ok` 表示最终有音轨，不能据此判断听感；全静音片也会通过这项检查。

## 6. 生成文件、修改和恢复

每次 `build_video.py` 必须写入新目录。运行 `--prepare-only` 时只准备文件；后续用 `compose.py` 合成。

| 文件 | 用途 |
| --- | --- |
| `project.json` | 本次输入参数快照 |
| `layout.json`、`card.png`、`layout_report.json` | 实际版式、标题卡与排版报告 |
| `shots.json`、`subs.json` | 实际镜头时间与字幕显示时间，可手改 |
| `compose_args.json` | 本次合成参数记录 |
| `center.mp4`、`soundtrack.wav`、`subtitles.mov` | 中央画面、混音、透明字幕中间文件 |
| `render_command.json` | 实际 FFmpeg 命令，只作本地运行记录 |
| `video.mp4`、`verify.json`、`result.json` | 成片、检查、合成结果 |

直接重合成教学例的写法如下。实际项目把路径、片长和声音参数换成本版值：

```sh
python tools/compose.py --config projects/demo/v1/layout.json \
  --card projects/demo/v1/card.png --shots projects/demo/v1/shots.json \
  --subs projects/demo/v1/subs.json --duration 8 \
  --music examples/demo/generated/music.wav --music-gain -5 \
  --out projects/demo/revised-v1/video.mp4 --work projects/demo/revised-v1 --verify
```

`compose.py` 不重画传入的标题卡。修改标题或布局后先用 `layout.py card --config 布局 --title 标题 --quote 底部文字 --out 新卡片` 更新，再合成。只改字幕或镜头时无需重画卡片。直接合成可覆盖给定的同名成片，因此手动操作也要使用新输出路径。

合成先写 `.partial.mp4`，完成解码、画布、音轨和时长检查后才替换目标文件。中断时保留工作目录；确认输入后可用记录中的配置重新运行 `compose.py`。生成命令与 ffconcat 会出现本机绝对路径，留在忽略目录，跨机器时重新生成。

## 7. 验证与具体问题

验证命令与看片清单见[验证说明](validation.md)。所有自动结果都应与本版文件对应。

| 现象 | 检查与处理 |
| --- | --- |
| 找不到素材或字体 | 核对路径从仓库根算起，并替换模板中的示例路径 |
| 改稿后镜头找不到句子 | `anchor` 对应字幕条的句首，更新锚点并保证唯一 |
| 字幕漏字或顺序不一致 | 核对实际声音与返回的字级时间；不改成字数均摊 |
| 文字超框 | 在保留意思的前提下调整显示换行、文本框或字号，不静默裁字 |
| 源视频不够长 | 转场也需要尾段；更换源区间或素材，不截最后一句 |
| 配音输入改变后被拒绝 | 为新声音使用新目录，保留旧回执和旧音频 |
| 流式断线后无法继续 | 没有 task_id 可续传；先核对已有回执，确定重做后另建目录 |
| 只修改主题记录而颜色未变 | 同时修改实际 `bands` 与 `fonts` 字段 |

当前校验固定为 1080×1920。源片段通过镜头表控制，`compose.py --center-out` 不生效。高级 Python 调用可传 `prepared_center` 与 `prepared_soundtrack` 复用中间文件，但只核对时长，不检查内容版本，常规使用重新渲染即可。Pexels 工具只取得候选并抽单帧，采用前还需核对连续片段。
